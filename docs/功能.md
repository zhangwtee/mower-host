# 功能

这套上位机有哪些功能、每项落在哪个文件哪个方法。行号不写——文件会改动，方法名相对稳定。

- 代码在 `ui/`，按职责分成 8 个模块，入口仍是 `ui/main_window.py` 里的 `MainWindow`
- 页面都用 `QStackedLayout` 切换，切页时窗口标题跟着换

---

## 一、主界面（8 个按钮）

左侧一列，从上到下：整机自检、开始割草、雷达跟随、自动回充、紧急停止、解除急停、SLAM地图、设置。

| 按钮 | 方法（`ui/main_window.py`） | 做什么 |
|---|---|---|
| 整机自检 | `start_self_test()` | 发 `CMD=5`，固件置自检标志；界面开始录像并计时，12 秒后 `_selftest_done()` 收尾 |
| 开始割草 | `start_mow()` | 弹窗选地图（只记日志，不加载）+ 开录像 + 打开绿色检测。**不下发刀片指令**，见 [移除记录.md](移除记录.md) |
| 雷达跟随 | `toggle_follow()` | 切跟随状态，再点一次停止。跟随逻辑在 `core/lidar_follower.py` |
| 自动回充 | `start_dock()` | 启 `DockController`：舵机 600↔2400 µs 扫掠，摄像头看到 AprilTag 进入对准。**对准之后的动作未实现**，见第十节 |
| 紧急停止 | `stop_all()` | 取消正在进行的准备流程、清叠加层（slam / Nav2 / rviz2）、发 `CMD=7` 触发**桥的急停锁存**；除「解除急停」外按钮全部禁用 |
| 解除急停 | `release_estop()` | 发 `/estop_release` 清桥的锁存，确认回来后恢复按钮 |
| SLAM地图 | `show_slam_page()` | 切到建图页 |
| 设置 | `show_settings()` | 切到设置页 |

顶部还有一行状态灯（见第七节）和两栏日志（发送 / 接收，各自可清空）。

## 二、设置页

**切换外设**是三选一，存进 `~/.割草机_config.json` 的 `hw_mode`：

| 选项 | 值 | 含义 |
|---|---|---|
| 摄像头(普通) | 0 | 只用 USB 摄像头 |
| 双目+激光雷达 | 1 | 深度相机 + 雷达 |
| 自动识别 | 2 | 由 `core/hw_detector.py` 按 USB VID:PID 判定 |

**清除缓存**：清空视频列表、清配置文件。

**速度显示**三种：仅仪表盘（`ui/speed_gauge.py`）、仪表盘 + 曲线、波形（`ui/waveform_widget.py`，pyqtgraph 滚动）。

## 三、建图（SLAM 页）

「开始建图」按下后：

1. **选模式**：异步 / 同步二选一（`_choose_slam_mode()`）。两者都是 `slam_toolbox`，区别只在节点可执行文件：`async_slam_toolbox_node` / `sync_slam_toolbox_node`。参数文件共用一份。取消弹窗则不启动。
2. **三级准备流程**（`_prepare()`，QTimer 状态机，每 500 ms 推进一步，界面不阻塞）：

   | 阶段 | 判定 | 超时 | 未就绪时 |
   |---|---|---|---|
   | 等待底盘桥 `/odom` | 有发布者 | 8 s | 进程死了就重拉桥，活着就继续等 |
   | 等待底层组 `/odom_combined` | 有发布者 | 12 s | 拉起 `mower_bringup`（EKF + 静态 TF + URDF） |
   | 等待雷达 `/scan` | 有发布者 | 8 s | 单起 `rplidar_node`（不整组带 `use_lidar`，避免复制第二套 EKF） |

   已在线的话题直接跳过；同一层已经拉起过且进程还活着，不会重复拉起。
3. **起叠加层**：`ros2 launch mower_slam mapper_online_async|sync.launch.py` + `rviz2 -d mower.rviz`。

任一阶段超时 → 状态栏显示「准备未完成」，按钮恢复，建图不启动。

**保存地图**（`_save_map()`）：后台线程跑 `map_saver_cli`，写进 `MAP_DIR`，文件名 `mymap_YYYYmmdd_HHMMSS`。带两个参数：

- `map_subscribe_transient_local:=false`（与 slam 发布端匹配）
- `save_map_timeout:=10.0`（大于 slam 的 `map_update_interval` 5 s）

外层 35 秒超时；失败时把 `[ERROR]`/`[WARN]` 关键行写进日志面板，并弹窗问「仍要停止 / 继续建图」。

**停止建图**（`_request_stop_mapping()`）：本次会话还没保存过会先问——「保存并停止 / 不保存直接停止 / 取消」。停止只清 slam 与 rviz2，底层组和桥保留。

## 四、导航（Nav2）

「Nav2 导航」→ 弹窗选已保存的地图 → 同一套三级准备流程 → `nav2_bringup bringup_launch.py`（`map:=` 选中的图、`params_file:=` 自研参数、`use_sim_time:=false`）→ 3 秒后另起 `rviz2`。

- 导航与建图互斥：启动导航前会先停掉建图叠加层
- 停止导航：`pkill` 掉 nav2 容器与各节点、`rviz2`，并调 `/stop_motor`
- 导航中不进入独立看图（避免两个 `map_server` 抢 `/map`）

## 五、地图库

卡片式列表（`_refresh_gallery()`），五项操作：

| 操作 | 方法 | 说明 |
|---|---|---|
| rviz2 查看 | `_open_map_rviz()` | 起独立 `map_server` 并激活 lifecycle，再开 rviz2 |
| 图片查看 | `_open_map_ppm()` | 直接解析 `.pgm`，在 Qt 窗口里显示 |
| 重命名 | `_rename_map()` | |
| 删除 | `_delete_map()` / `_delete_selected_maps()` | 支持多选 |
| 刷新 | `_refresh_gallery()` | 按时间倒序扫 `MAP_DIR/mymap*.yaml` |

## 六、摄像头与录像

`ui/camera_widget.py` 提供画面，`ui/camera.py` 负责窗口与录像：

- 实时画面 + 录像写入 `~/Videos/割草机`
- AprilTag 检测（`core/tag_detector.py`，`DICT_APRILTAG_36H11`，ID 0），回充靠它对准
- 绿色检测，割草时打开
- 录像时另开一个「录制中」预览窗，合成摄像头 + 曲线 + 数值

## 七、状态灯

顶部五个灯：底盘 / 雷达 / EKF / 建图 / 导航。**每 2 秒刷新一次**（`_refresh_leds()`），

| 灯 | 判定 |
|---|---|
| 底盘 | `/odom` 有发布者 |
| 雷达 | `/scan` 有发布者 |
| EKF | `/odom_combined` 有发布者 |
| 建图 | `/map` 有发布者 |
| 导航 | `/plan` 有发布者 |

在线为绿、离线为灰；鼠标悬停显示对应话题名。灯反映的是**当前**话题状态，不是启动时的快照。

## 八、底盘桥（`bridge/`，ROS2 包 `mower_bridge`）

节点 `chassis_bridge` 是上位机与底盘之间唯一的串口通道。

| 方向 | 话题 | 类型 |
|---|---|---|
| 订 | `/cmd_vel` | `geometry_msgs/Twist` |
| 订 | `/servo_cmd` | `std_msgs/Int16` |
| 订 | `/selftest_cmd` | `std_msgs/Empty` |
| 订 | `/emergency_stop` | `std_msgs/Empty` |
| 订 | `/estop_release` | `std_msgs/Empty` |
| 发 | `/odom` | `nav_msgs/Odometry` |
| 发 | `/imu/data_raw` | `sensor_msgs/Imu` |
| 发 | `/PowerVoltage` | `std_msgs/Float32` |

另外：

- 0.5 秒看门狗：`/cmd_vel` 超时没新指令就补一帧零速度，节点退出前也补一帧
- Mahony 互补滤波出四元数（EKF 的 `imu0_config` 里 yaw = true，姿态必须真算）
- 不发 TF，`odom_combined → base_footprint` 由外部 `robot_localization` 出
- 参数：`port` `baud` `odom_*_scale` `cmd_vel_timeout` `frame_id_*`
- 不解析 19 字节超声波帧，割草机没有该硬件
- 固件上电后 10 秒内丢弃所有指令（`CONTROL_DELAY`）

## 九、协议层

- `bridge/mower_bridge/protocol.py` 是权威实现（发 11 字节、收 24 字节）
- `core/protocol.py` 只组发帧，用于离线自检与无 ROS 环境；改协议时两边一起改

离线自检（不需要硬件）：

```bash
python3 core/protocol.py                # 组帧字节序列
python3 bridge/test/test_protocol.py    # 组帧 / 解析 / 重同步 / Mahony
```

帧格式与 CMD 表见 [协议.md](协议.md)。

## 十一、还没做的

### 11.1 自动回充只走到对准

现在能跑的：按「自动回充」→ `DockController.start()` → 状态 `SWEEPING`，30 ms 定时器把舵机在 600↔2400 µs 之间扫；摄像头看到 AprilTag → `tag_detected()` → 状态转 `VERIFYING`，状态栏显示「对准中...」。

到此为止：`_tick()` 只在 `SWEEPING` 分支里动作，进入 `VERIFYING` 后舵机停住；`on_done` 没有调用方；全程没有下发过速度指令，车不动。

要接的部分（协议里命令字已有，桥里常量也在）：

| CMD | 固件行为 | 用途 |
|:---:|---|---|
| 1 / 2 | 写 `charger.Up_MoveX/Y/Z`，置 `AllowRecharge = 1` | 远距离开回充电桩 |
| 3 | 写 `charger.Dock_MoveX/Y/Z`，不动 `AllowRecharge` | 近距离红外对接微调 |

缺的环节：Tag 居中/距离判定 → CMD=3 横向微调 → 判断是否旋转 → CMD=1/2 进桩退桩 → 读电压确认充电 → 失败重试。接上之前车不会动，所以没有失控风险；一旦接上，必须先测通急停链路，见 [DISCLAIMER.md](../DISCLAIMER.md)。

### 11.2 命令没有回执（只有效果确认）

协议只有下行发帧，没有序号/回执字段，固件也没有 ACK 位。界面能做到的不是"确认收到"，而是"确认产生了预期效果"：

| 命令 | 判断依据 | 没说清的部分 |
|---|---|---|
| 速度 `/cmd_vel` | 编码器实测速度连续 3 帧跟上指令（1.5 s 内） | 车本来就在该速度（滑行）时只报「无需确认」，不谎报生效 |
| 急停 | 实测速度 600 ms 内归零 | — |
| 自检 | 3 秒内观测到车确实动起来（固件自检第一拍设 `Vx=0.3`） | 只能看"动没动"，看不自检是否通过 |
| 舵机 | 上行帧没有舵机回读 | 只报「已发送」 |
| 刀片 | **控制已整套移除**，界面没有按钮、桥也不发 `CMD=6` | 无 |

桥把这些结果以 JSON 发到 `/cmd_ack`，界面据此显示「已确认停止」「未确认停车」「速度未跟上」。

**急停锁存由桥维护**：固件的 `emergency_stop` 在 `SelfTest_Run()` 里立刻清零、不锁存，`CMD=8` 没有对应分支。桥在锁存期间丢弃 `/cmd_vel` 并每 0.5 秒补零速帧，直到 `/estop_release`。

**桥启动即锁存**（参数 `estop_on_start`，默认 true）：断电重启或桥崩溃重启后，车不会因为一帧残留指令就动，必须有人按「解除急停」。锁存状态用 latched 的 `/estop_state` 发布，界面半路重启也能回到正确状态。

「停掉上一个任务、准备开新任务」走的是**软停**（`/soft_stop`），不触发锁存：桥在 `soft_stop_hold` 秒（默认 1 秒）内把所有来源的速度都强制压成零，然后自动恢复。它比直接发一条零速 `/cmd_vel` 可靠——桥是串口唯一出口，Nav2 或跟随那一路盖不掉它。

只有主界面的「紧急停止」才发 `CMD=7` 触发锁存。

真正的帧级回执需要在下行帧里加序号、上行帧里加回执位，属于固件改动——本机固件没有上传途径，暂不做。
